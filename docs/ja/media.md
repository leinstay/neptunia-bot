# メディアと知覚

ペルソナが何を見て、聞いて、読めるか、そしてそれを可能にするヘルパーについて。

トランスクリプトの行にはメディアマーカーが括弧で表示されます: 画像、GIF、動画、スティッカー、カスタム絵文字、ボイスメッセージ、音声ファイル、リンク、テキストファイルのプレビュー、転送されたメッセージ。ペルソナが実際に何を知覚するかは以下の機能に依存します。ユーザーメッセージの `<senses>` ブロックが、現在の設定で何が有効で何が無効かをペルソナに伝えます。ペルソナはこのブロックを信頼し、そこに記載されている以上のものを見た、聞いた、開いたと主張しません。

## 画像

`features.vision` は呼び出しメッセージ、リプライ先のメッセージ、チャンネル内の最新の画像を、Discord のメディアプロキシ経由でダウンスケールして LLM リクエストに画像として添付します。ボットはすべての画像を自分でダウンロードし、データとしてインライン送信します。Discord がモデルプロバイダーからのダウンロードを拒否するためです。`context.vision.maxBytes` を超える画像や `context.vision.fetchTimeoutMs` より遅い画像はスキップされます。ペルソナはこれらを直接見ます。

`features.mediaDescriptions`（デフォルト有効）は `classifier.media` モデルを使い、画像、GIF フレーム、動画ポスター、スティッカー、カスタム絵文字、リンクサムネイルに対して一行の説明文を書きます。各添付ファイルは一度だけ記述され、`data/guilds/<id>/media.json` にキャッシュされます。説明文はチャットのトランスクリプト、メモリアナライザー、ウォームアップに供給されます。説明モデルのプロンプトは `prompts/describe.md` です。

スティッカーとカスタム絵文字は頻繁に繰り返されるため、ID でキャッシュされ、初回の記述後はほぼコストがかかりません。`features.vision` が有効な場合、呼び出しメッセージのスティッカーは画像として添付されます。Discord の組み込みアニメーションスティッカーは Lottie アニメーションであり画像ではないため、名前以上の情報は得られません。

設定: 直接ビジョンは `context.vision.*`、説明モデルは `media.*` 配下にあります。全キーの詳細は[設定リファレンス](configuration.md#media)を参照してください。

## 動画

`features.videoDescriptions`（デフォルト無効、`config.local.json` で有効化、`mediaDescriptions` も必要）は `classifier.video` モデルを追加し、短いクリップを視聴します。対象は Discord の動画添付ファイルと既知の動画サイトへのリンク（YouTube、TikTok、VK、X、Reddit、Twitch）です。モデルは OpenRouter を通じて動画と音声の両方の入力を受け付ける必要があります。

### クリップと上限

添付ファイルとダウンロードしたサイト動画は `media.video.maxSeconds`（デフォルト 60 秒）と `media.video.maxBytes` で制限されます。`directUrlMaxSeconds`（デフォルト 180 秒）以内の YouTube リンクは URL としてプロバイダー（Google AI Studio）に渡されます。ターンあたり最大 `maxPerTurn` 件の新規動画（成否を問わずすべての試行がカウント）、1 日あたり `maxPerDay` 件です。結果は画像の説明文と同じキャッシュに保存されるため、再投稿のコストはかかりません。

### ツール

上限内の添付ファイル以外はすべて `yt-dlp` でダウンロードされ `ffmpeg` でトリムされます。どちらもオプションのシステムバイナリです。これらがなくても上限内の添付ファイルはそのまま動作します（そのまま送信されます）。長い添付ファイルとすべてのサイトリンクは静止フレームにフォールバックします。YouTube の場合、`yt-dlp` が再生時間を取得できないときは、`.env` のオプションの `YOUTUBE_API_KEY`（無料、Google Cloud コンソールの YouTube Data API v3）またはウォッチページのスクレイプが補完します。`/nep ping classifier.video` はこのホストでどのソースが動作するかを報告します。

### 質問に対する再視聴

ペルソナがすでに視聴済みの動画について質問された場合、分類器（`prompts/rewatch.md`、`classifier.text` ロール）が再視聴の必要性を判定します。必要な場合、動画モデルが `prompts/rewatch-answer.md` でクリップを再度視聴し、回答がオリジナルのサマリーと共にトランスクリプトに表示されます。同じ分類器は、読み込めなかった動画について再度問い合わせがあった場合にリトライすることもできます。ターンあたり最大 1 回の再視聴またはリトライ。回答は 1 時間キャッシュされます。スイッチ `features.videoRewatch`（デフォルトオン）。

動画プロンプトは `prompts/describe-video.md` です。設定は `media.video` 配下にあります。全キーとモデル比較表については[設定リファレンス](configuration.md#mediavideo)を参照してください。

## リンク: ページの読み取り

`features.webLookup`（デフォルトオフ。他の機能と異なり、キーが存在しない場合はオフとして扱われる）を有効にすると、ペルソナはチャットに投稿されたリンクを開いて読み取れます。

機能が有効で `web.links.enabled` が false でない場合、トランスクリプト内のリンク（http/https のみ、プライベートアドレスは拒否、動画サイトリンクは除外、`web.links.skipSites` は除外）は SSRF ガード付きページフェッチャーでフェッチされます（サイズ上限 `web.links.maxBytes`、タイムアウト `web.links.fetchTimeoutMs`、最大 3 リダイレクト、html とプレーンテキストのみ）。ページテキストは `classifier.text` モデルが `prompts/read-link.md` を通じて最大 `web.links.summaryChars` 文字の抜粋に要約します。抜粋はリンクのトランスクリプトタグに `transcript.linkRead` として追加され、ファーストハンドとして表示されます: ペルソナがその抜粋の範囲内でページを自分で開いて読みました。読み取れないページ（ペイウォール、同意画面、ログインゲート、空のコンテンツ）は検出されミスとしてキャッシュされます。

`web.links.prefill` が有効（デフォルト）の場合、リンクは到着した時点で読み取られ、次のターンでキャッシュ済みの状態になります。プリフィルはメンバーあたり 1 日 `web.links.prefillPerUserPerDay`（デフォルト 10）で制限されます。ターンパスはこの制限を受けません。ターン中の各フェッチ試行は `web.links.maxPerTurn`（デフォルト 2）にカウントされます。リンク読み取りと検索は日次カウンター `web.maxPerDay`（デフォルト 60）を共有します。

読み取り結果はメディアキャッシュに保存されます: `read:<link.id>` が抜粋またはミス（6 時間スキップ）を保持します。`<senses>` ブロックには機能が有効な場合に `senses.linksRead` が含まれ、リンクに読み取り抜粋が付随する可能性があることをペルソナに伝えます。

## 検索

ペルソナに話しかけられたとき、トリガーメッセージがチャット外の事実を必要とする場合、分類器（`prompts/lookup.md`、`classifier.text` ロール）がウェブ検索クエリを作成します。検索は Brave Search（`.env` の `BRAVE_SEARCH_API_KEY`。無料枠: 2,000 クエリ/月、以降は 1,000 クエリあたり $5）を通じて実行され、番号付きの結果が `prompts/search-summary.md` で要約され、回答が `<chat>` の直前に `<lookup>` ブロックとして表示されます。

分類器が発火するのは以下のすべてが成立する場合のみです: トリガーがある、`features.webLookup` がオン、`web.search.enabled` が false でない、`lookup.md` プロンプトが存在する、`web.search.maxPerTurn` が 1 以上、`BRAVE_SEARCH_API_KEY` が設定されている。キーがない場合、リンク読み取りは動作しますが検索は動作しません。

ターンあたり最大 1 回の検索。分類器と要約はそれぞれ `llm.maxRequestsPerDay` にカウントされます。結果は正規化されたクエリごとに `web.search.cacheHours`（デフォルト 24）時間キャッシュされます。`<senses>` ブロックには Brave キーが設定されている場合にのみ `senses.search` が含まれます。

設定は `web` 配下にあります。全キーの詳細は[設定リファレンス](configuration.md#web)を参照してください。プロンプトファイルとコードの間のコントラクトは[プロンプトコントラクト](prompt-contract.md)にあります。

## ボイス、音声、その他の盲点

ボイスメッセージは長さのみ表示されます。音声ファイルは名前と長さが表示されます。ペルソナはどちらも聞くことができません。盲点をどう扱うかはキャラクターカード次第です。

## コスト

各ターンは一つの LLM リクエストで、メモリ更新が二つ目を追加します。動画説明文は視聴したクリップごとに `classifier.video` モデルへ 1 リクエストを追加します（`media.video.maxPerDay` で 1 日の件数を制限）。`yt-dlp` と `ffmpeg` はローカルで実行され、帯域幅以外のコストはかかりません。リンク読み取りと検索は `classifier.text` モデルへのリクエストを追加し、`web.maxPerDay`（共有）と `llm.maxRequestsPerDay`（グローバル）で制限されます。検索にはさらに Brave Search キーが必要です。無料枠で低トラフィックのサーバーに対応できます。

## 外部リクエストとプライバシー

`features.webLookup` が有効な場合、ボットはページ読み取りと Brave Search API への送信 HTTP リクエストを行います。ページはホストから直接フェッチされます。プライベートアドレス（ループバック、リンクローカル、プライベート範囲）は拒否されます。ページコンテンツは要約のために LLM エンドポイントを通じて `classifier.text` モデルに送信されます。ページテキストも検索クエリもログに記録されません。`data/` にはキャッシュされた抜粋と検索結果がマシン上に保存され、gitignore 対象で、LLM にはコンテキストとしてのみ送信されます。
