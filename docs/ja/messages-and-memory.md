# メッセージとメモリ

ペルソナがメッセージを処理し、人々を記憶する仕組み。

## パイプライン

メッセージはギルド、チャンネル、自身のメッセージのフィルターを通過します。ペルソナが呼ばれた場合（@メンション、リプライ、名前トリガー）、無視ヒューリスティクスがベースの確率に対してロールし、素のピング、繰り返しタグ、スパム、発話者の関係スコアで調整されます。ロールに失敗した場合、メッセージは無視されます。無視されたメッセージは次のリプライ構築時にトランスクリプトに含まれます。

ペルソナが誰かに応答した後、そのチャンネルの次の `mention.followUpMinutes` 分間のタグなしメッセージは `classifier.text` ロールの分類器に送られ、やり取りが続いているか判定します。3 回連続で `no`（`mention.followUpNoStreak`）が出るとウィンドウが閉じます。フォローアップウィンドウは再起動後も維持されます。`features.followUp` でオフにできます。

自発的なターンはカオスタイマーまたはメッセージごとの盗み聞き確率（`spontaneous.eavesdropChance`）から発生します。`spontaneous.maxChannelSilenceHours` 時間以上沈黙したチャンネルでは、ペルソナは自発的に発言しません。ただし直接のピングには応答します。

### 一度に一つ

ペルソナはサーバー全体で一度に一つのリプライを書きます（`mention.oneAtATime`）。`mention.pendingSameChannel` がオン（デフォルト `true`、キー欠落 = オン）のとき、ターン実行中の同じチャンネルに届いた直接ピング（@メンションまたはペルソナのメッセージへのリプライ）は保留されます。チャンネルごとに 1 件、ターン終了後に `mention.switchDelayMs` の待機で応答し、その時点で無視確率が判定されます。実行中のターンがそのピングをすでに履歴で処理済みの場合、二重に応答しません。スイッチオフの場合、ピングは見逃され、次のリプライのトランスクリプトに含まれるだけです。別のチャンネルからの直接ピングも同様に保留されます。チャンネルごとに 1 件、最大 `mention.maxPending` チャンネルで `mention.pendingMinutes` 分間保持されます。同じ保留チャンネルに新しいピングが来ると古いものが置き換えられます。現在のリプライが完了すると、ペルソナは短いポーズ（`mention.switchDelayMs`）の後にチャンネルを切り替え、その時点の会話から応答します。通常の無視確率が適用されます。ビジー中の名前トリガーや盗み聞きヒットはスキップされます。`mention.oneAtATime: false` の場合、チャンネルごとに独立して処理されます。ペルソナは Send Messages 権限がない場所では書き込みもリアクションもしません。LLM リクエストを消費する前に確認します。ただしそうしたチャンネルは読み取られ記憶されます。

### リクエスト

ターンはチャンネルのトランスクリプトと隣接チャンネルを収集し、トークンバジェット内で一つの LLM リクエストを構築します。セクションは優先順に充填されます。システムプロンプトとタスクは決してカットされません。続いて発話者のプロファイル、ウェブルックアップの結果、サーバーの傾向と自己言及、チャンネルマップ、ロアブックエントリ、トランスクリプト（新しい順）、他のプロファイル、隣接チャンネルの順です。

モデルにはサーバーのチャンネルマップ（目的、トピック、トーン、アクティビティレベル）が表示され、現在のチャンネルがマークされます。各チャンネルエントリにはコードが管理するファクトも含まれます: メッセージ数、最初と最後のメッセージ、30 日間のアクティビティヒストグラム、トップライター。ウォームアップがチャンネルの履歴から充填し、ライブトラフィックが最新に保ちます。

モデルは `<think>`（隠れた計画）、`<msg>`（1〜3 件のチャットメッセージ。`reply="#87"` でトランスクリプトの行にリプライ）、`<react>`（絵文字リアクション一つ）、`<skip/>`（沈黙）で応答します。解析後、人間の速度でタイピングがシミュレートされ、出力内の `@nick` が実際のメンションに変換されます。

## アナライザー

メモリアナライザーは十分なメッセージが蓄積した時点で別の LLM 呼び出しとして実行されます（`memory.batchMessages`、`memory.minBatchMessages`、`memory.maxBatchAgeMinutes`）。キャラクターカードを受け取り、キャラクターの目を通して各人を判断し、態度の変化、プロファイルの変更、チャンネルの観察、サーバーレベルのノートを返します。

### プロファイル

プロファイルは差分更新されます: アナライザーは変更があったものだけを返し、保存された事実が再要約されることはありません。各プロファイルには以下が含まれます:

- **キャラクターとスタイル**: ウォームアップ時にプロファイルプロンプト（`profile.md`）が全文を書き込む自由記述の段落で、アナライザーがギャップや矛盾を指摘した際に最近のメッセージからリフレッシュされます。ストリームアナライザーは直接編集しません。一行のポートレートヒントを返し、コードがポートレートリフレッシュをキューに入れます。
- **関心**: トピックとノートを持つアトミックな項目。頻度と新しさでランク付けされ、重みは時間とともに減衰します（`memory.interestHalfLifeDays`）。表示されるよりも多くの項目がメンバーごとに保持されるため（`memory.maxInterestsStored` vs `memory.maxInterests`）、新規項目は表示されない末尾で重みを蓄積できます。`memory.interestStaleDays` 以上目撃されていない関心は古いものとしてペルソナに表示されます。
- **詳細**: アトミックな項目（事実、特徴、コンテキスト情報）。関心と同じランキングと確定の仕組みで、独自の半減期（`memory.detailHalfLifeDays`）を持ちます。
- **エイリアス**: チャットの中で人々が実際にメンバーを呼ぶ名前。ペルソナは名前やエイリアスで言及されたメンバーが会話に参加していなくても認識します。
- **関係**: ペルソナとこの人がどういう関係にあるか。ペルソナの声で記述されます。
- **態度**: -100 から 100 のスコア（`features.relationships`）。アナライザーは小さな差分を返し、絶対スコアは設定しません。スコアはチャットに表示されません。ペルソナがどれだけ労力をかけるかに反映されます。`relationships.decayPerDay` が設定されている場合、スコアは毎日ゼロに向かってドリフトし、ゼロから遠いほど速くなります。テキストが書かれたときと別の段階にスコアが移っていると、保存済みの relationship テキストはアナライザーが更新するように書き直しフラグが立てられます。

メンバーのキャラクターと話し方のポートレートは `memory.mainChannelIds` のチャンネルから作成されます。リストが空の場合はすべてのチャンネルが対象です。保存されたメモリはメンバーを ID で参照し、使用時に現在の名前が置換されるため、名前の変更で保存されたノートが壊れることはありません。

### 確定

関心、詳細、エイリアスは確定メカニズムを共有します。新しい項目は重み 1 で始まります（アナライザーが `"sure": false` をマークした場合は 0）。別の機会（少なくとも `memory.confirmGapHours` 間隔）に目撃されると重みが 1 上がります。項目は重みが `memory.confirmAfter` に達すると確定されます。それまではペルソナに「(未確定)」マーク付きで表示されます。項目は `log2(weight + 0.5) + lastSeen / halfLife` でランク付けされるため、頻繁かつ最近のものが上位に来ます。

## エピソード

エピソードはペルソナが個々の人について記憶する出来事です: 侮辱、親切、約束、賭け、共有されたジョーク、ペルソナに何かを頼んだこと、あるいは決してしないよう頼んだこと。アナライザーは日付、短い説明、時にはその人自身の言葉、1 から 5 の重みとともにプロファイルに追記します。重いものほど長く残ります。プロファイルが `memory.maxEpisodes` に達すると、最も軽いものから先に削除され、次に最も古いものが削除されます。表示されるのは発話者のエピソードのみで、`<people>` ブロック内に含まれます。

## ロアブック

ロアブックはサーバー全体の知識を保存します。会話を超えて残るもの: イベント、繰り返し登場するキャラクター、長期にわたるストーリー、対立、伝統。各エントリにはタイトル、キーワードセット、短いテキスト（`lore.textChars`）があります。コードは直近の `lore.scanMessages` 件のメッセージをキーワードマッチでスキャンし、最大 `lore.maxMatches` エントリを `<lore>` ブロックに含めます。`always` とマークされたエントリは常に表示されます。マッチする少数だけが表示されるため、数百のエントリが存在してもコストはほぼゼロです。

アナライザーは独自にロアブックエントリを追加・更新しますが、オーナーが `/nep lore` コマンドで追加したエントリには手を触れません。ロアブックデータは `data/guilds/<id>/lore.json` に保存されます。

アナライザーは、人々がペルソナに直接教えたこと — 言葉や表現、サーバーに関する事実、振る舞いに関するリクエスト — もサーバーレベルのレッスンとして記録し、常にプロンプトに含まれます。

## プライベートレイヤー

`features.privateMessages` がオンの場合、ゲートを通過したメンバー（ギルドメンバーシップ、保存されたプロファイル、公開アフィニティが `private.minAffinity` 以上、本日のリプライ数がキャップ未満）が Discord DM でペルソナと会話できます。ペルソナは同じキャラクター、同じ公開メモリ。DM で話された内容はメンバーごとのプライベートレイヤーに保存されます。

メンバーのプライベートレイヤーを確認できるのはボットオーナーのみです（`/nep private show`）。このコマンドは他のユーザーにグラントできません。

プライベートファイル `data/guilds/<guildId>/private/<userId>.json` は独自の `relationship`、`interests`、`details`、`episodes`、`affinity`（初期スコア 0）、日次リプライカウンター、観察バッファーを保存。他の会話には表示されず、サーバーバッチで書き込まれず、ディスク上の公開プロファイルと混合されません。

DM ではペルソナは公開とプライベートデータの結合を見ます: インタレストはトピックで結合（プライベートノートが優先）、ディテールは連結、エピソードは日付順。実効アフィニティは `clamp(公開 + プライベート, -100, 100)`。サーバーでは公開スコアのみ。

`/nep memory forget <user>` は公開プロファイルとプライベートファイルの両方を削除。`/nep memory wipe` はサーバーの `private/` ディレクトリ全体を削除。`/nep private forget <user>` はプライベートファイルのみを削除し、公開プロファイルは保持。

## コマンド

全コマンドの一覧は[コマンド](owner-commands.md)にあります。メモリに関連する主なコマンド:

| コマンド | 動作 |
|---|---|
| `/nep memory show <user>` | 保存されたプロファイルのコンパクトな要約または特定のセクション |
| `/nep memory channel` | 保存されたチャンネルノートとコードが管理するファクト |
| `/nep memory server` | サーバー全体の傾向、内輪ネタ、自己言及 |
| `/nep memory refresh <user>` | メンバーのポートレートリフレッシュを強制実行 |
| `/nep memory forget <user>` | 保存されたプロファイルとプライベートメモリを削除 |
| `/nep memory affinity <user>` | 態度の表示または設定 |
| `/nep memory wipe` | サーバーのアナライザーメモリをすべて消去（プライベートファイル含む） |
| `/nep private show <user>` | メンバーのプライベートメモリを表示 |
| `/nep private forget <user>` | プライベートファイルのみを削除。公開プロファイルは保持 |
| `/nep lore add` | ロアブックエントリの追加または上書き |
| `/nep pause` / `/nep resume` | アクティビティを停止し、安全な手動編集のためにメモリをディスクにフラッシュ |
