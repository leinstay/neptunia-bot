# Конфигурация

Все ключи `config.json` со значениями по умолчанию, по секциям.

|---|---|---|

| `eavesdrop` | `true` | Случайный шанс вклиниться после любого сообщения |
| `memory` | `true` | Строить профили, отслеживать серверные паттерны, записывать факты о себе |
| `relationships` | `true` | Баллы отношения к каждому участнику (-100..100) |
| `episodes` | `true` | Долгосрочные воспоминания по каждому человеку (моменты, цитаты, обиды) |

| `customEmoji` | `true` | Показывать серверные пользовательские эмодзи, ранжированные по использованию, чтобы персонаж мог писать `:name:`. Отсутствующий ключ считается включённым |
| `gifs` | `true` | Собирать библиотеку GIF из того, чем делятся участники (ссылки Tenor, Giphy и .gif-вложения), и позволять персонажу отправлять из неё по хэндлу. Отсутствующий ключ считается включённым |

Отсутствующий ключ считается включённым. Требует `vision` и `mediaDescriptions`; один дополнительный запрос к описателю на картинку, в рамках `media.maxPerTurn` |

| `webLookup` | `false` | Читать ссылки, опубликованные в чате, и искать в интернете, когда задан фактический вопрос. В отличие от остальных переключателей, отсутствующий ключ считается ВЫКЛЮЧЕННЫМ. Для поиска нужен `BRAVE_SEARCH_API_KEY` в `.env`; без него работает только чтение ссылок. См. [Медиа: ссылки и поиск](media.md#ссылки) |
| `imageGeneration` | `false` | Разрешить персонажу рисовать картинки через подпроцесс рисования. Отсутствующий ключ считается включённым. Включается в `config.local.json`; нужна модель с поддержкой генерации изображений в `image.model`. См. [Медиа: рисование](media.md#рисование) |

| `mentor` | `false` | Ручной подпроцесс тестирования со своей моделью. Должен быть строго `true` для включения; отсутствующий ключ считается выключенным. См. [Ментор](#mentor) |

| `followUp` | `true` | После ответа персонажа классифицировать сообщения без обращения: продолжается ли разговор |
| `typingSimulation` | `true` | Имитировать скорость набора |
| `adminCommands` | `true` | Слэш-команды владельца; `false` отменяет их регистрацию |

## `llm`

| Ключ | По умолчанию | Описание |
|---|---|---|
| `baseUrl` | `"https://openrouter.ai/api/v1"` | Эндпоинт chat completions |
| `model` | `"anthropic/claude-opus-4.6"` | ID модели |
| `temperature` | `1` | Температура сэмплирования |
| `maxOutputTokens` | `700` | Макс. токенов на выходе |
| `maxRequestTokens` | `50000` | Жёсткий лимит токенов на запрос |
| `safetyMargin` | `0.9` | Доля `maxRequestTokens`, доступная бюджету |
| `timeoutMs` | `300000` | Таймаут запроса (мс) |
| `pingTimeoutMs` | `30000` | Таймаут для запросов `/nep ping` (мс) |
| `retries` | `2` | Повторы при временных ошибках |
| `maxRequestsPerDay` | `300` | Дневной лимит запросов |
| `provider` | `null` | Объект маршрутизации OpenRouter `provider`, передаётся как есть; `null` = поле не отправляется |

`llm.provider` задаёт поле маршрутизации провайдера OpenRouter в каждом запросе, например `{ "ignore": ["some-provider"] }` или `{ "order": ["anthropic"], "allow_fallbacks": true }`. Если аккаунт OpenRouter ограничивает допустимых провайдеров, исключение единственного оставшегося даст ошибку "No endpoints found" на каждом запросе. После изменения настроек провайдера выполните `/nep ping`, чтобы проверить доступность каждой роли модели.

## `classifier`

Три вспомогательные роли моделей, объединённые под одним ключом. Каждая настраивается независимо: вспомогательные модели могут оставаться на дешёвых, пока голос использует премиальную.

| Ключ | По умолчанию | Описание |
|---|---|---|
| `text` | `"anthropic/claude-sonnet-4.6"` | Текстовые классификаторы: классификатор обращений (`features.followUp`), классификатор повторного просмотра (`features.videoRewatch`) и классификатор поиска (`features.webLookup`). Также сжимает прочитанные ссылки и результаты поиска |
| `media` | `"anthropic/claude-haiku-4.5"` | Описания картинок (`features.mediaDescriptions`): однострочные описания для картинок, кадров GIF, постеров видео, стикеров, пользовательских эмодзи и превью ссылок |
| `video` | `"google/gemini-3.8-flash"` | Описания видео (`features.videoDescriptions`): смотрит короткие клипы, пересматривает по вопросу, повторяет по запросу. Должна принимать и видео, и аудио на входе |

**Переход со старых ключей.** Устаревшие ключи `llm.classifierModel`, `mention.followUpModel`, `media.model` и `media.video.model` больше не читаются. Если какой-либо из них присутствует в `config.local.json`, бот выводит предупреждение при запуске (`config: deprecated model key ignored`) с именем ключа и его заменой. Перенесите значение в `classifier.text`, `classifier.media` или `classifier.video` соответственно.

### `context.customEmoji`

Настройки блока пользовательских эмодзи (`features.customEmoji`). Анализатор памяти отслеживает, какие пользовательские эмодзи используют участники и как часто.

| Ключ | По умолчанию | Описание |
|---|---|---|
| `max` | `30` | Пользовательских эмодзи в блоке `<emoji>`, ранжированных по использованию участниками; когда ранжированных меньше `max`, список дополняется остальными серверными эмодзи в серверном порядке |
| `storeMax` | `200` | Пользовательских эмодзи, хранимых в рейтинге использования; показываются лучшие `max` |
| `halfLifeDays` | `30` | Период полураспада новизны для рейтинга использования (дней); rank = log2(count + 0.5) + last / halfLife; давно не используемый эмодзи опускается ниже часто используемого |
| `backfillMessages` | `500` | Сообщений на канал, читаемых из истории при старте для первичного заполнения рейтинга. Выполняется один раз, когда `features.customEmoji` включён и заполнение для этого сервера ещё не запускалось; результат записывается в `guild.json`. `0` отключает |

| Ключ | По умолчанию | Описание |

| `max` | `20` | GIF, показываемых в блоке `<gifs>`, ранжированных по частоте и новизне использования |
| `storeMax` | `300` | GIF, хранимых в библиотеке; показываются лучшие `max` |
| `halfLifeDays` | `30` | Период полураспада новизны для рейтинга использования (дней); та же формула, что для пользовательских эмодзи |
| `maxPerDay` | `40` | GIF, которые персонаж может отправить за день |
| `backfillMessages` | `500` | Сообщений на канал, читаемых из истории при старте для первичного заполнения библиотеки. Выполняется один раз, когда `features.gifs` включён и заполнение для этого сервера ещё не запускалось. `0` отключает |
| `backfillDescribe` | `20` | Топ GIF по рангу, отправляемых описателю для подписи сразу после заполнения; остальные получают подписи при встрече в чате |

### `media.video`

Настройки модели описаний видео (`features.videoDescriptions`). Для зрения видео нужны оба переключателя: `features.mediaDescriptions` и `features.videoDescriptions`. Видеомодель: `classifier.video`. Отдельная модель с поддержкой видео смотрит короткие клипы: видеовложения Discord и ссылки на сайты из `media.video.sites`. Результаты кэшируются в общем кэше медиа рядом с описаниями картинок; повторная публикация ничего не стоит.

| Ключ | По умолчанию | Описание |
|---|---|---|
| `provider` | `{ "order": ["google-ai-studio"], "allow_fallbacks": false }` | Маршрутизация провайдера OpenRouter для пути с прямым URL (YouTube в пределах лимита длительности); `null` использует `llm.provider` |
| `maxOutputTokens` | `800` | Макс. токенов на выходе на описание видео |
| `summaryChars` | `1500` | Макс. символов для описания видео; заполняет `{{maxChars}}` в `describe-video.md` |
| `maxRequestTokens` | `60000` | Лимит токенов на запрос видео (вход + выход), используется вместо `llm.maxRequestTokens`. Видео по публичному URL в agentic-режиме оценивается через `directUrlTokensPerSecond` (10): час YouTube занимает 36 000 токенов. Скачанные клипы оцениваются через `tokensPerSecond` (120): три минуты занимают 21 600 токенов |
| `maxSeconds` | `180` | Макс. длительность клипа (секунд) для вложений и скачанных видео с сайтов; более длинные вложения обрезаются `ffmpeg`, более длинные видео с сайтов обрезаются до первых `maxSeconds` через `yt-dlp`. Для сайтов с прямым URL используется `directUrlMaxSeconds` |
| `directUrlMaxSeconds` | `3600` | Макс. длительность (секунд) для видео по публичному URL (YouTube и другие `directUrlSites`) в agentic-режиме (`urlProcessing`). В других режимах действует меньшее из этого значения и `maxRequestTokens / tokensPerSecond`. Более длинные видео идут путём скачивания (первые `maxSeconds` через yt-dlp), и YouTube часто блокирует это проверкой на бота на серверах |
| `maxBytes` | `12000000` | Макс. размер файла (байт) для вложений и скачанных клипов с сайтов; само скачивание может быть до 4x от этого размера. Превышающие лимит файлы сначала перекодируются в 360p через `ffmpeg`; только клип, всё ещё слишком большой после перекодирования, отклоняется как постоянное непопадание |
| `maxPerTurn` | `1` | Макс. НОВЫХ видео за ход; каждая попытка считается, удачная или нет |
| `maxPerDay` | `40` | Дневной лимит запросов на видео (хранится в `state.json` как `videoDay`/`videoCount`) |
| `tokensPerSecond` | `120` | Оценка токенов на секунду видео для проверки бюджета. Применяется к скачанным клипам и к видео по публичному URL вне agentic-режима; в agentic-режиме вместо неё используется `directUrlTokensPerSecond` |
| `directUrlTokensPerSecond` | `10` | Оценка токенов в секунду для предварительной проверки бюджета при передаче видео по публичному URL в agentic-режиме (модель загружает только нужное, само видео не считается токенами промпта). При отсутствии или невалидном значении используется `tokensPerSecond`. `tokensPerSecond` (120) по-прежнему применяется к скачанным клипам и к URL в других режимах |
| `timeoutMs` | `90000` | Таймаут запроса к LLM для видео (мс) |
| `toolTimeoutMs` | `60000` | Таймаут подпроцессов `yt-dlp` и `ffmpeg` (мс) |
| `sites` | `["youtube.com", "youtu.be", "tiktok.com", "vk.com", "vkvideo.ru", "x.com", "twitter.com", "reddit.com", "twitch.tv"]` | Хосты, ссылки на которые считаются видео |
| `directUrlSites` | `["youtube.com", "youtu.be"]` | Сайты, чей публичный URL можно передать провайдеру напрямую (провайдер сам загрузит видео) |
| `directUrlUnknownDuration` | `false` | Передавать ссылку directUrlSites-сайта провайдеру, даже если ни один проб не определил длительность; оценка токенов использует `maxSeconds`. См. цепочку определения длительности ниже |
| `canaryUrl` | `"https://www.youtube.com/watch?v=jNQXAC9IVRw"` | Фиксированное YouTube-видео, проверяемое при старте и по `/nep ping classifier.video` для тестирования YouTube API key и источников длительности |
| `ytdlpPath` | `"yt-dlp"` | Путь к утилите `yt-dlp`; нужна для видеоссылок и определения длительности |
| `ffmpegPath` | `"ffmpeg"` | Путь к `ffmpeg`; нужен для обрезки и уменьшения длинных или тяжёлых вложений |
| `errorRetryMinutes` | `60` | Минут до повторной попытки для видео с ошибкой; принудительный повтор от классификатора повторного просмотра игнорирует этот интервал |
| `urlProcessing` | `"agentic"` | Режим обработки OpenRouter для видеочастей с публичным URL; без него некоторые провайдеры видят только один кадр. `null` убирает поле |

Утилиты `yt-dlp` и `ffmpeg` опциональны. Без них вложения в пределах лимитов работают (отправляются как есть). Длинные вложения и все ссылки на видеосайты откатываются к стоп-кадру или превью-картинке, а персонажу сообщается причина. Каждый запрос к видеомодели считается в `llm.maxRequestsPerDay` и в лимит токенов видео (`maxRequestTokens`).

Для YouTube-ссылок длительность определяется по цепочке: сначала yt-dlp, затем YouTube Data API (при наличии `YOUTUBE_API_KEY` в `.env`), затем разбор watch-страницы. Если все пробы провалились и `directUrlUnknownDuration` выключен (по умолчанию), ссылка сообщается как «не удалось загрузить». При включённом переключателе URL всё равно отправляется провайдеру, а в оценке токенов считается как `maxSeconds`. Ключ Data API бесплатен: включите YouTube Data API v3 в Google Cloud console и создайте ключ; бесплатная квота: 10 000 единиц/день, один запрос длительности стоит 1 единицу. `/nep ping classifier.video` проверяет `canaryUrl` и сообщает статус API key (например `youtube: API key — ok`). Закэшированный результат «превышение лимита длительности» запоминает длительность видео и повторяется при повышении лимита.

### `media.video.rewatch`

Настройки ручного подпроцесса тестирования (`features.mentor`). Ментор придумывает чат-ситуации, прогоняет через них персонажа в песочнице и оценивает ответы. Использует собственную модель и собственный дневной бюджет токенов; ничего из его работы не считается в `llm.maxRequestsPerDay`. Все настройки перезагружаются на лету.

| Ключ | По умолчанию | Описание |
|---|---|---|
| `model` | `null` | ID модели ментора. `null` или отсутствует — все команды, требующие модель, сообщают об этом |
| `maxTokensPerDay` | `400000` | Дневной бюджет токенов. Считается по реальному использованию: токены промпта x1, кэшированные токены промпта x`cachedTokenWeight`, токены вывода x`outputTokenWeight`. Ответы персонажа в песочнице считаются так же |
| `outputTokenWeight` | `5` | Вес токенов вывода в бюджете. Учитывает более высокую стоимость генерации |
| `cachedTokenWeight` | `0.1` | Вес кэшированных токенов промпта в бюджете |
| `maxOutputTokens` | `6000` | Макс. токенов на выходе за запрос ментора |
| `timeoutMs` | `300000` | Таймаут запросов ментора (мс) |
| `situations` | `5` | Чат-ситуаций за прогон |
| `situationLines` | `[6, 15]` | Мин. и макс. строк на ситуацию |
| `samples` | `3` | Ответов персонажа на каждую ситуацию |
| `check.samples` | `1` | Ответов персонажа на ситуацию при `/nep mentor check` |
| `pass.score` | `7` | Кейс считается пройденным, если медиана `overall` и медиана `goal` достигают этого порога |
| `pass.floor` | `5` | Кейс проваливается, если медиана любой оси ниже этого минимума. Каждая ситуация тоже проверяется по этому минимуму: кейс проваливается, если медиана `overall` или медиана `goal` любой одной ситуации ниже его, какими бы ни были медианы по всем ответам |
| `diagnose` | `true` | После проваленного или слабого прогона ментор объясняет, что в контексте привело к слабым ответам. Сохраняется как `diagnosis` в прогоне; check никогда не запрашивает |
| `suspects` | `2` | Причин из диагностики, проверяемых за попытку в цикле исправления |
| `ablationGain` | `1` | Минимальный рост медианы `overall` при удалении подозреваемого для его подтверждения |
| `ablationSamples` | `2` | Ответов персонажа на ситуацию при абляции |
| `fix.maxAttempts` | `3` | Макс. попыток исправления за прогон |
| `fix.maxGrowthChars` | `300` | Макс. символов, на которые файл промпта может вырасти за одну правку |
| `fix.layers` | `["rules", "prompt", "self", "learned", "guild"]` | Слои, доступные для правки. Карточка персонажа никогда не редактируется. Деплой может добавить `profile` в список |
| `fix.files` | `["system-prompt", "format", "reply", "memory", "profile"]` | Файлы промптов, которым можно создать локальное переопределение. Для reply-кейса пересекается с `system-prompt`, `format`, `reply`; memory-кейс правит только промпты писателя памяти, только через слой `prompt` |
| `regression.situations` | `2` | Сохранённых ситуаций каждого другого активного кейса, воспроизводимых при проверке регрессии |
| `regression.tolerance` | `1` | Допустимое падение медианы `overall` сохранённой ситуации относительно её записанной медианы |
| `verify.situations` | `3` | Свежих ситуаций для верификации правки |
| `verify.samples` | `2` | Ответов персонажа на ситуацию при верификации |
| `verify.minSituations` | `2` | Минимум свежих ситуаций после фильтрации; при нехватке попытка отклоняется как `too few fresh situations` |
| `reference.days` | `7` | Дней истории чата для построения стилевого эталона |
| `reference.samples` | `60` | Случайных строк (2–200 символов) из окна эталона в качестве примеров стиля |
| `reference.maxMessages` | `3000` | Макс. сообщений, прочитанных из каналов эталона |
| `reference.rarePer1000` | `0.5` | Знак, используемый реже этого числа раз на 1000 символов, считается редким |
| `reference.rareMinAuthors` | `2` | Знак, используемый меньшим числом авторов, считается редким |
| `anchor.max` | `5` | Реальных моментов на кейс. Каждый момент — сообщение персонажа, которое владелец отклонил, сохранённое вместе с предшествующим чатом |
| `anchor.contextMessages` | `30` | Сообщений канала, загружаемых как контекст при разрешении момента, заканчивая триггером |
| `anchor.hideLaterMemory` | `true` | При воспроизведении реального момента скрывать память, записанную в момент триггера или позже (эпизоды, изменения отношения, детали, интересы, псевдонимы, усвоенные элементы, записи лора). `false` воспроизводит со всей сегодняшней памятью |
| `feedbackExamples` | `10` | Последних поправок владельца (`/nep mentor wrong`), включаемых в каждый запрос оценки |

`llm.maxRequestTokens` (50k на запрос) применяется к каждому запросу ментора и к ответам песочницы. Перед каждым запросом ментора проверка бюджета учитывает промпт плюс максимум, который может стоить ответ (`mentor.maxOutputTokens` при `mentor.outputTokenWeight`), поэтому запрос отклоняется, когда его возможный вывод не помещается в остаток. При исчерпании бюджета прогон останавливается и отчитывается о том, что успел. Прогон также останавливается, если `features.mentor` или `mentor.model` отключены во время его работы, или если в каналах эталона нет сообщений людей в окне эталона.

При правке профиля участника (слой `profile`) код проверяет, что числа, даты, имена и упоминания `<@id>` в поле остались без изменений. Меняться может только формулировка.

## Модели

Движок использует пять ролей моделей. Каждая настраивается независимо: голос может работать на премиальной модели, а вспомогательные на дешёвых.

### Голос (`llm.model`)

Роль `talk`. Наиболее мощная модель, которую позволяет бюджет. Качество ролеплея, стабильность характера и естественность разговора полностью зависят от неё. Более слабая модель выходит из роли, игнорирует подсказки контекста и звучит плоско.

По умолчанию: `anthropic/claude-opus-4.6`. Бюджетный вариант: `anthropic/claude-sonnet-4.6`.

### Анализатор (`memory.model`)

Роль `analyzer`. Рассуждает над длинными транскриптами и возвращает строгий JSON. Нужен тот же уровень интеллекта, что и для голоса. `null` (по умолчанию) использует модель персонажа. Применимы те же рекомендации.

### Текстовые классификаторы (`classifier.text`)

Самая дешёвая текстовая модель, способная надёжно отвечать «yes» или «no». Используется для классификатора обращений, классификатора повторного просмотра, классификатора поиска, а также для сжатия прочитанных ссылок и результатов поиска. По умолчанию: `anthropic/claude-sonnet-4.6`.

### Картинки (`classifier.media`)

Любая дешёвая модель со зрением. Пишет однострочные описания, поэтому мощность рассуждений почти не важна.

По умолчанию: `anthropic/claude-haiku-4.5`. Самая дешёвая альтернатива: `google/gemini-2.5-flash-lite`.

### Видео (`classifier.video`)

Здесь подходят только модели, принимающие ОДНОВРЕМЕННО видео и аудио на входе через OpenRouter. Модели, принимающие кадры, но не аудио (Qwen VL, GLM, Seed, Gemma), не слышат речь и упускают большую часть смысла.

`google/gemini-flash-latest` это плавающий псевдоним, цена которого может измениться без предупреждения. Пакетные (`:batch`) варианты асинхронны и непригодны для ответа в реальном времени. Путь с прямым URL (YouTube в пределах лимита длительности, отправляется как публичный URL с `media.video.provider`) требует Google AI Studio в качестве провайдера.

Стоимость одноминутного клипа, USD, по ценам OpenRouter на 2026-09-23:

| Модель | ~USD / 1 мин клип |
|---|---|
| `google/gemini-2.5-flash-lite` | 0.002 |
| `google/gemini-3.1-flash-lite` | 0.005 |
| `google/gemini-3.5-flash-lite` | 0.006 |
| `google/gemini-3.7-flash` | 0.014 |
| `google/gemini-3.8-flash` (default) | 0.014 |

`qwen/qwen3.8-omni-flash` тоже принимает видео и аудио. Цены меняются; таблица лишь снимок на дату выше.

### Ментор (`mentor.model`)

Роль `mentor`. Оценивает ответы персонажа и придумывает тестовые ситуации. Рекомендуется модель из другого семейства, чем модель голоса: модель слепа к привычкам собственного семейства. `null` (по умолчанию) оставляет ментора отключённым; команды `/nep mentor`, требующие модель, сообщают об этом.

### Генерация картинок (`image.model`)

Отдельно от `classifier.media` (который описывает входящие картинки). Эта модель генерирует картинки через OpenRouter Images API (`POST /api/v1/images`). Поддерживаются только два семейства: `openai/*` и `google/*`. Неподдерживаемое семейство отклоняется до отправки запроса или подсчёта.

**Модели OpenAI.** Учитывают `image.openai.quality`, `image.openai.background`, `image.openai.moderation`, `image.aspectRatio`, `image.outputFormat` и `input_references`.

| Модель | Примечания |
|---|---|
| `openai/gpt-image-2.5-flare` (default) | Быстрый тир |
| `openai/gpt-image-2.5-sunburst` | Тир высокой точности |
| `openai/gpt-image-2` | |
| `openai/gpt-image-1` | |
| `openai/gpt-image-1-mini` | |

**Модели Google.** Учитывают `image.google.resolution`, `image.aspectRatio`, `image.outputFormat` и `input_references`. `image.aspectRatio` со значением `auto` не отправляется в запросе Google.

| Модель | Примечания |
|---|---|
| `google/gemini-3.1-flash-image` | Nano Banana 2 |
| `google/gemini-3-pro-image-preview` | |
| `google/gemini-2.5-flash-image` | Без параметра разрешения |

Тарификация за выходные токены, а не за картинку; `usage.cost` от провайдера показывается в `/nep draw` и логируется. Запрос, отклонённый движком до отправки (дневной или пользовательский лимит, неподдерживаемое семейство моделей), ничего не стоит; генерация, отклонённая провайдером, как правило, не тарифицируется; таймаут или неудачная загрузка картинки, которая уже была сгенерирована, могут быть тарифицированы.
