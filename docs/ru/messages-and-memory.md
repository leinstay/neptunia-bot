# Сообщения и память

Как персонаж обрабатывает сообщения и запоминает людей.

## Конвейер сообщений

Сообщение проходит через фильтры гильдии, канала и собственных сообщений. Если персонаж был вызван (@упоминание, ответ или триггер по имени), эвристика игнорирования бросает кость с базовым шансом, скорректированным за пустые пинги, повторные обращения, спам и балл отношения вызвавшего. Если бросок не прошёл, сообщение игнорируется; проигнорированные сообщения остаются в транскрипте при построении следующего ответа.

После того как персонаж ответил кому-то, сообщения без обращения в этом канале на протяжении `mention.followUpMinutes` минут отправляются классификатору на роли `classifier.text`, который определяет, продолжают ли они разговор; три `no` подряд (`mention.followUpNoStreak`) закрывают окно. Окна follow-up переживают перезапуск. `features.followUp` выключает классификатор.

Спонтанные ходы запускаются хаотичным таймером или шансом подслушивания на каждое сообщение (`spontaneous.eavesdropChance`). Персонаж не будет говорить спонтанно в канале, молчащем дольше `spontaneous.maxChannelSilenceHours` часов; прямой пинг туда по-прежнему получает ответ.

### Один ответ за раз

Персонаж пишет один ответ за раз на весь сервер (`mention.oneAtATime`). Пинг в том же канале, пока персонаж уже отвечает, пропускается; пропущенные сообщения остаются в транскрипте при построении следующего ответа. Прямой пинг в другом канале (@упоминание или ответ на сообщение персонажа, не триггер по имени) откладывается, по одному на канал, в не более чем `mention.maxPending` каналах на `mention.pendingMinutes` минут; более поздний пинг в том же отложенном канале заменяет более ранний. Когда текущий ответ завершён, персонаж переключает канал после короткой паузы (`mention.switchDelayMs`) и отвечает по ситуации в разговоре; обычный шанс игнорирования применяется. Триггеры по имени и попадания подслушивания, пришедшие, пока персонаж занят, пропускаются. При `mention.oneAtATime: false` каждый канал обрабатывается независимо. Персонаж никогда не пишет и не реагирует там, где у него нет права Send Messages, проверяя это до траты запроса к LLM; такие каналы по-прежнему читаются и запоминаются.

### Построение запроса

Ход собирает транскрипт канала и соседние каналы, затем строит один запрос к LLM в рамках бюджета токенов. Секции заполняются по приоритету: системный промпт и задача не обрезаются никогда; затем профиль вызвавшего, результат веб-поиска, серверные привычки и факты о себе, карта каналов, записи лорбука, транскрипт (новейшие сначала), остальные профили и соседние каналы.

Модель видит карту каналов сервера (назначение, темы, тон, уровень активности) с текущим каналом, отмеченным специально. Каждая запись канала также содержит факты, которые ведёт код: количество сообщений, первое и последнее сообщение, гистограмму активности за 30 дней и самых активных авторов. Прогрев заполняет их из истории канала, и живой трафик поддерживает их актуальность.

Модель отвечает тегами `<think>` (скрытое планирование), `<msg>` (1–3 сообщения в чат; `reply="#87"` — ответ на строку транскрипта), `<react>` (одна эмодзи-реакция) или `<skip/>` (молчание). После разбора набор имитируется с человеческой скоростью, а `@nick` в выводе становится реальным упоминанием.

## Анализатор памяти

Анализатор памяти запускается как отдельный вызов LLM, когда накопится достаточно сообщений (`memory.batchMessages`, `memory.minBatchMessages`, `memory.maxBatchAgeMinutes`). Он получает карточку персонажа и оценивает каждого человека глазами персонажа, возвращая дельты отношения, изменения профилей, наблюдения по каналам и серверные заметки.

### Профили

Профили обновляются инкрементально: анализатор возвращает только то, что изменилось, и сохранённые факты никогда не пересказываются. Каждый профиль содержит:

- **Характер и стиль** — прозаические абзацы, написанные целиком промптом профиля (`profile.md`) при прогреве и обновляемые из недавних сообщений, когда анализатор отмечает пробел или противоречие. Потоковый анализатор никогда не редактирует их напрямую; он возвращает однострочную подсказку для портрета, и код ставит обновление в очередь.
- **Интересы** — атомарные элементы с темой и заметкой. Ранжируются по частоте и новизне с весом, затухающим со временем (`memory.interestHalfLifeDays`). На каждого человека хранится больше элементов, чем показывается (`memory.maxInterestsStored` против `memory.maxInterests`), поэтому новичок может набирать вес в невидимом хвосте. Интересы, не встречавшиеся `memory.interestStaleDays` дней, показываются персонажу как устаревшие.
- **Детали** — атомарные элементы (факт, черта, контекст). Те же механики ранжирования и подтверждения, что у интересов, со своим периодом полураспада (`memory.detailHalfLifeDays`).
- **Псевдонимы** — как люди в чате реально называют участника. Персонаж узнаёт участника, упомянутого по имени или псевдониму, даже если тот не в разговоре.
- **Отношения** — как персонаж и этот человек стоят друг к другу, написано голосом персонажа.
- **Отношение** — балл от -100 до 100 (`features.relationships`). Анализатор возвращает небольшую дельту, никогда не абсолютный балл. Балл не показывается в чате; он проявляется в том, сколько усилий персонаж вкладывает.

Портрет характера и манеры речи участника строится по каналам из `memory.mainChannelIds`; когда список пуст, все каналы считаются основными. Сохранённая память ссылается на участников по id, и текущее имя подставляется при использовании, поэтому переименования не ломают заметки.

### Механизм подтверждения

Интересы, детали и псевдонимы используют общий механизм подтверждения. Новый элемент начинает с веса 1 (или 0, когда анализатор помечает его `"sure": false`). Наблюдение на отдельном случае (с промежутком не менее `memory.confirmGapHours`) увеличивает вес на 1. Элемент считается подтверждённым при весе ≥ `memory.confirmAfter`; до этого персонаж видит его с пометкой «(не подтверждено)». Ранг элементов: `log2(weight) + lastSeen / halfLife`, поэтому частое И недавнее наверху.

## Эпизоды

Эпизоды — это моменты, которые персонаж помнит об отдельных людях: оскорбление, доброта, обещание, пари, общая шутка, просьба что-то сделать или никогда не делать. Анализатор добавляет их в профиль человека с датой, кратким описанием, иногда дословными словами и весом от 1 до 5. Самые тяжёлые живут дольше всего; когда профиль достигает `memory.maxEpisodes`, сначала вытесняются самые лёгкие, затем самые старые. Только эпизоды вызвавшего показываются — внутри блока `<people>`.

## Лорбук

Лорбук хранит серверные знания, которые переживают любой разговор: события, повторяющихся персонажей, длительные истории, конфликты, традиции. Каждая запись содержит заголовок, набор ключевых слов и короткий текст (`lore.textChars`). Код сканирует последние `lore.scanMessages` сообщений на совпадение ключей и включает до `lore.maxMatches` записей в блок `<lore>`; записи с пометкой `always` появляются всегда. Записей могут быть сотни при ничтожных затратах, потому что показываются только подходящие.

Анализатор добавляет и обновляет записи лорбука самостоятельно, но никогда не трогает записи, добавленные владельцем через команды `/nep lore`. Данные лорбука хранятся в `data/guilds/<id>/lore.json`.

## Команды владельца для работы с памятью

Полный список команд: [Команды](owner-commands.md). Наиболее важные для памяти:

| Команда | Что делает |
|---|---|
| `/nep memory show <user>` | Краткая сводка или конкретная секция сохранённого профиля |
| `/nep memory channel` | Сохранённые заметки канала и факты, которые ведёт код |
| `/nep memory server` | Серверные привычки, внутренние шутки, факты о себе |
| `/nep memory refresh <user>` | Принудительно обновить портрет участника |
| `/nep memory forget <user>` | Удалить сохранённый профиль |
| `/nep memory affinity <user>` | Показать или установить отношение (-100..100) |
| `/nep memory wipe` | Стереть всю память анализатора для этого сервера |
| `/nep lore add` | Добавить или перезаписать запись лорбука |
| `/nep pause` / `/nep resume` | Остановить активность и сбросить память на диск для безопасного ручного редактирования |
